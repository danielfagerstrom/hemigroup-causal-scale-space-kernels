% ---------------------------------------------------------------------------------
% NUMBERING: one chapter per draft section, chapter number == section number.
% ---------------------------------------------------------------------------------
%
% theorems.tex masters one shared counter off `definition`, reset per chapter. The draft
% (draft/hemigroup-causal-scale-space-kernels.md) numbers exactly the same way, one
% shared counter per section: Definition 2.1, Definition 2.2, Proposition 2.3, Lemma 2.4;
% Lemma 9.1 ... Remark 9.11. So starting the chapter counter at 1 and giving each draft
% section its own chapter makes the blueprint's numbering IDENTICAL to the draft's --
% Lemma 4.1 is Lemma 4.1, Theorem 7.3 is Theorem 7.3, Remark 9.11 is Remark 9.11.
%
% That is what makes the two documents reviewable side by side, and what will let
% paper/main.tex share statements without a renumbering table. Every node also carries a
% `% draft: <kind> N.M` provenance comment, so the correspondence is explicit and does
% not rest on the counter alone.
%
% Consequence, deliberate: the standalone PDF starts at Chapter 2. There is no Chapter 1
% because \S1 of the draft is the introduction, which is positioning rather than
% mathematics and is not transcribed. Renumbering to close the gap would cost the
% draft-alignment above, which is worth far more.
%
% Scope is \S\S2-14, the mathematics. \S1 (introduction) and \S15 (concluding remarks)
% stay in the draft. REVISED 2026-09-01 (author's instruction): \S13 (implementation) and
% \S14 (the temporal N-jet) were originally excluded to keep the blueprint's size under
% control; the author now wants the blueprint complete with respect to the mathematical
% material, with formalisation a separate decision -- so chapters 13-14 carry statement
% nodes without \lean tags, and none is scheduled in a Lean phase.

% The .tex extensions below are explicit for the reader's sake; all three consumers
% accept either form (pdflatex natively, `linkage` by appending .tex when absent,
% plasTeX through kpsewhich).
%
% What IS load-bearing, and cost several CI runs to find: plasTeX resolves every
% \input through kpsewhich, and its fallback when that binary is missing is an exact
% filename match against a directory listing -- which can never resolve a name
% containing a separator. So on a machine without a working kpsewhich, web.tex and
% content.tex resolve while every parts/* file is silently dropped, and the web build
% renders a complete-looking site with no statement nodes in it. The shared docs
% workflow installs texlive-base for this and asserts kpsewhich before building.
% Adding .tex does not help; the separator is the issue.
